# negaudit

付费搜索账户的否定关键词冲突审计库（仅标准库）。

## 用法

```go
acc, invalid, err := negaudit.LoadAccount(r) // r 为账户 JSON
recs := negaudit.Audit(acc)                  // 全部冲突记录，顺序确定
```

命令行：

```
go run ./cmd/negaudit account.json
```

每个非法条目、每条冲突各输出一行。

## 账户 JSON 结构

```json
{
  "campaigns": [
    {
      "name": "c1",
      "negatives": ["-free"],
      "shared_lists": ["common"],
      "ad_groups": [
        {"name": "g1", "keywords": ["buy shoes"], "negatives": []}
      ]
    }
  ],
  "shared_lists": {"common": ["-[cheap]"]}
}
```

关键词的适用否定词 = 所在广告组 + 所在系列 + 该系列挂载的每个共享列表。

## 文本规则

- 去首尾空白；否定词允许一个前导 `-`。
- `[...]` 完全匹配，`"..."` 词组匹配，否则广泛匹配；首/尾出现 `[` `]` `"`
  却不构成完整包裹的为非法条目。
- 去包裹后按 Unicode 转小写，字母、数字、`&` 以外的字符视为空白切词；
  0 个或超过 10 个词为非法条目。
- 非法条目与指向不存在共享列表的挂载会被跳过并随位置报告。

## 冲突级别

- `critical`：否定词阻断了关键词能匹配的每一条搜索词。
- `warning`：不构成 critical，但阻断了由关键词自身词序列构成的搜索词。

## 性能

不做逐对比较：每个来源（广告组/系列/共享列表）的否定词只索引一次，
共享列表不随挂载次数复制；每个关键词枚举自身的精确键、全部连续子序列
与词集子集（≤ 2^10）查询全局索引。满规模账户（5000 关键词 × 2 万条
适用否定词）单核约 33ms（Apple M1 Max），内存与否定词条目总数成线性。

- `audit_test.go`：对拍测试——随机生成关键词/否定词覆盖九种匹配方式
  组合，与在有限搜索词集合上穷举的参照实现比对（集合充分性的论证见
  测试注释）；另有级别判定表驱动用例与确定性检查。
- `load_test.go`：JSON 加载、非法条目与悬空挂载报告。
- `bench_test.go`：满规模账户基准测试。
